Regulatorkoden slik den står implementerer {\it direktevirkning}, siden feilen beregnes som PV $-$ SP.

\vskip 10pt

Følgende tillegg gir regulatoren mulighet til å bytte mellom direkte og omvendt reguleringsvirkning:

$$\includegraphics[width=15.5cm]{i01486x02.eps}$$

\hbox{ \vrule
\vbox{ \hrule \vskip 3pt
\hbox{ \hskip 3pt
\vbox{ \hsize=5in \raggedright

\noindent
\underbar{\bf Pseudokodelisting}

\vskip 10pt

{\tt Deklarer Pin0 som analog inngang (skalering 0 til 5 volt = 0 til 1023)}

{\tt Deklarer Pin1 som analog utgang (skalering 0 til 5 volt = 0 til 1023)}

{\tt Deklarer Pin7 som digital inngang}

{\tt Deklarer SP som variabel, initialt satt til 614}

{\tt Deklarer GAIN som variabel, initialt satt til 1.0}

{\tt Deklarer ERROR som variabel}

{\tt Deklarer BIAS som konstant = 614}

\vskip 10pt

{\tt LOOP}

\hskip 10pt {\tt IF Pin7 = 0, SETT ERROR = Pin0 - SP }

\hskip 10pt {\tt ELSE, SETT ERROR = SP - Pin0}

\hskip 10pt {\tt ENDIF}

\vskip 10pt

\hskip 10pt {\tt SETT Pin1 = (GAIN * ERROR) + BIAS}

{\tt ENDLOOP}
}
\hskip 3pt}%

\vskip 10pt

Selv om svært treg programkjøring kan være dårlig for regulering, kan det faktisk være nyttig i enkelte prosesser. I prosesser med stor dødtid (transportforsinkelse) brukes en reguleringsstrategi kalt {\it sample-and-hold}, og det er nettopp hva dette programmet blir hvis en bevisst og betydelig forsinkelse legges inn i løkka.
