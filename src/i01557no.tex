Digitale regulatorer beregner den tidsderiverte av et inngangssignal ved å sample signalet gjentatte ganger (analog-til-digital-konvertering) og utføre matematisk analyse mellom samplene. Her er en ``pseudokode''-algoritme en digital datamaskin kan bruke for å beregne et inngangssignals endringsrate over tid:

\hskip 10pt {\tt SET x = input} \hskip 10pt {\it // (Sample input signal and set 'x' equal to that value)}

\hskip 10pt {\tt SET t = system\_time} \hskip 10pt {\it // (Sample system clock and set 't' equal to that value)}

\vskip 10pt

\hskip 10pt {\tt SET last\_t = t} \hskip 10pt {\it // (Set 'last\_t' equal to the current value of 't')}

Forklar hvordan denne algoritmen virker, ved å beregne endringsrate basert på påfølgende samplinger av inngangsvariabelen og systemklokken (tid).

\vskip 20pt \vbox{\hrule \hbox{\strut \vrule{} {\bf Forslag til sokratisk diskusjon} \vrule} \hrule}

\begin{itemize}
\item{} Anta at rekkefølgen på de to siste SET-instruksjonene byttes om. Hvordan vil denne endringen påvirke programdriften, hvis i det hele tatt?
\item{} Anta at SET-instruksjonen ``t = system\_time'' slettes fra programmet. Hvordan vil denne endringen påvirke programdriften, hvis i det hele tatt?
\item{} Anta at mikroprosessoren oppgraderes slik at programmet kjører med dobbelt normal hastighet (dvs. ``loop'' gjennom algoritmen dobbelt så ofte som før). Hvordan vil denne endringen påvirke beregningen av endringsrater, hvis i det hele tatt?
\end{itemize}

%(BEGIN_ANSWER)

Den vanskeligste delen å forstå er forholdet mellom {\tt x} og {\tt last\_x}, og mellom {\tt t} og {\tt last\_t}. Denne teknikken med å deklarere et variabelpar og sekvensielt la en verdi flyttes fra én variabel til den neste i hver løkkeiterasjon, brukes ofte i mange ulike algoritmer. Hensikten med teknikken er å gi en måte å måle endring i en variabel (som {\tt x} og {\tt t}) for hver skann av programmet. Når endring i både $x$ og $t$ er kjent, kan kvotienten (deriverten) beregnes ved å dele den ene endringen på den andre.

%(END_ANSWER)
